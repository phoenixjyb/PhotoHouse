# PH-A0: local agent runtime qualification

**October 20, 2026 finding: the tested stock Codex configuration fails the
original exact three-tool policy. This record does not qualify activation.**
This is a developer-only synthetic protocol finding, not a local-model or
Windows runtime qualification. The [PH-A1 application boundary](LOCAL_AGENT_RUNTIME.md)
remains default off; [PH-U0](LOCAL_AGENT_ACCEPTANCE.md) is unmeasured and the
[PH-A4 story draft contract](SELECTED_SOURCE_STORY_DRAFT_CONTRACT.md) remains a
proposal.

The revised [household development plan](LOCAL_AGENT_DEVELOPMENT_PLAN.md)
replaces a fixed product tool count with workflow-specific capabilities and
helper review. The original failure evidence below is retained unchanged. A
policy mismatch is not itself proof of unauthorized disclosure, and revising
the policy does not turn this run into a pass under a new profile.

The source increment is based on PH-A1 freeze
`23733e2eb4f94a4ee474ea0746b0633b12589c9f`, itself based on main
`a4e39221a3dab8ee84bacc7c9226e7b3a71b112b`. Application/client/package-builder
source is unchanged by this qualification increment.

## Exact binary and configuration

The tested macOS arm64 binary identifies as `codex-cli 0.163.0`, SHA-256:

```text
8813367285524ac798dd96d1b071aea30d58708c7226fd236cd275cf1cfdee31
```

Stable app-server JSON schemas were generated by that binary. Each probe creates
an empty temporary working directory and `CODEX_HOME`, strips inherited
credentials/proxies, and generates a catalog from that binary's bundled
metadata. Its synthetic model alias identifies a protocol fixture, not a real
model. No personal config/auth, production database or household media is used.
The captured `thread/start` response reports no instruction sources.

The configuration disables shell/image/browser/computer/plugin/hook/app/goal/
memory features, web search, unbounded connection retries and WebSockets. The
catalog explicitly sets `shell_type="disabled"`,
`apply_patch_tool_type=null`, `node_repl_disabled=true` and `tool_mode="direct"`.
MCP is required and `enabled_tools` contains exactly the three PH-A1 operations.
The binary accepts this configuration under `--strict-config`. The effective
thread is ephemeral, read-only, with approval policy `never` and sandbox network
access false. These settings do not establish process-wide egress confinement,
zero persistence or the tool ceiling.

## Reproducing the limited probe

[The probe](../tools/probe_agent_runtime.py) uses only Python's standard library.
It starts owned, authenticated literal-loopback synthetic HTTP servers and the
explicitly selected binary. It never launches a real model or reconfigures an
existing inference service. Its HTTP fixtures are test instruments, not the
PH-A2 production gateway: they do not implement the complete gateway's
authorization, connection/flood accounting or application callbacks.

Use an absolute binary path and digest verified for the intended build. The
evidence directory must be new and private, outside source control:

```sh
python3 tools/probe_agent_runtime.py \
  --binary /absolute/path/to/codex \
  --sha256 <verified-binary-sha256> \
  --evidence /private/new/evidence/allowed \
  --scenario allowed
```

Repeat with `forbidden_resource`, `unknown`, `http_503`, `dropped_stream` and
`connection_close`, using a different new evidence directory for each. Each
report records the probe source digest, binary digest/version, counts, terminal
status and scoped findings. Captures contain only synthetic traffic; bearer
values are redacted. Full model input, bundled metadata, temporary paths and
protocol traces are retained privately for inspection. Do not adapt this probe
to read personal configuration or send household content.

Exit `2` means an observed capability-ceiling failure, including runs whose
protocol terminal status was `completed`. Exit `1` means the probe did not
complete its protocol observation. Exit `0` means a scoped observation completed
without an observed ceiling failure; it is never a PH-A0 pass certificate.
Inspect the separate `allowed_round_trip`, `turn_status`,
`negative_transport_single_attempt`, cleanup and error fields. A final selector
cannot hide a denied domain call or a failed turn.

The tool limits stdout frames/cumulative output, stderr and event buffering,
denies unexpected host RPC, signals its own POSIX process group with TERM and
escalates to KILL if the root does not exit within two seconds.
`owned_root_exit` only reports its owned root process exit. If a root exits first,
this utility does not establish that every descendant exited; unsettled drains
are recorded as cleanup errors. It does not certify native descendant
containment, API crash/restart recovery or provider-compute termination. No
shared provider is killed.

Offline probe checks:

```sh
python3 -m unittest tools.tests.test_probe_agent_runtime
python3 tools/verify_current_source.py
```

The 15 targeted tests cover real fixture HTTP auth/origin/host/body refusal,
recorded resource denial, bounded owned-child output/teardown, unexpected host
RPC denial, capability reporting and evidence redaction. They start no Codex or
model. Existing full API results belong to the PH-A1 freeze; this developer tool
does not justify reclassifying them as model or runtime acceptance.

## Gates still open and next development choice

The local Ollama service was reachable read-only as version `0.40.6`, with zero
installed and zero loaded models. Consequently there was no real local-model
canary. A localhost route does not establish local inference: server no-cloud
state, backend/weights identity, outbound destinations and retention still need
evidence. No weights were downloaded and no service was restarted.

Native Windows containment and API crash/restart reconciliation, provider-stop
signals, resource admission against competing GPU jobs, actual model tool
competence/latency, PH-U0 product benefit and family/device acceptance are all
unqualified. The application lane remains off.

The stock ordinary-MCP adapter cannot be activated on this evidence. Runtime
selection stays open under the revised household plan. Define the useful
workflow and its permitted domain operations/helpers before comparing a stock
runtime, narrowly modified build or application-owned loop. A selected-source
story task may use the existing direct narrative adapter without a general
agent loop. Do not build a replacement merely to remove extra tool names.
Preserve application authorization, source/replay fencing and shared resource
ownership in every design, and qualify actual dispatch under its exact profile.
Dynamic tools, if selected, are a separate design rather than ordinary MCP
callbacks. Direct narrative output uses its own validator; it does not inherit
the PH-A1 search selector grammar.

No push, merge, deployment, runtime activation or release publication is part of
this increment. App-server remains an experimental integration surface under
the [official app-server documentation](https://learn.chatgpt.com/docs/app-server);
a successful private fixture would not change that upstream support boundary.
