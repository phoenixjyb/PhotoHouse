# Recent assistant turns

The Web search assistant shows the last eight successful current-page exchanges
with distinct user and assistant labels. Each turn is plain text. A bounded,
keyboard-accessible scroll region follows a new reply only when the reader was
already at its end. Reading older turns preserves the first visible surviving
row and its offset; a localized **跳到最新 / Jump to latest** control appears
outside the scroll region. If the eight-turn cap removes every visible row,
reading resumes at the oldest remaining exchange. Current result cards and their explicit open
actions retain the existing behavior.

Each displayed exchange has a client-local identity independent of reply text
or optional server receipts. Identical replies remain distinct. New replies do
not move page position or keyboard focus. Explicit Jump focuses the list without
scrolling the page; native scrolling or keyboard End clears the indicator at the
end. Same-account/library language refresh preserves reading position and the
indicator. Scroll controls do not record, submit, resend or request history.

This list clears on refresh, sign-out, account/library changes and pending-turn
recovery. Failed, malformed, uncertain or delayed old-scope responses cannot
enter it. The heading describes the current page; it does not promise deletion
of server records. Assistant troubleshooting records have their own configured
30-day retention, while assistant recordings remain transient.

The visible list is not sent as hidden model history. A later explicit command
uses the existing bounded structured filters and visible IDs. Story and memoir
conversations use their separate persisted history and context contracts. Phone
search has its own forty-exchange process-memory list. Stable local request keys
keep pending and completed rows related without trusting an optional server
receipt. New replies follow the actual end of the newest item only when the
reader is following it; a manual drag interrupts automatic movement. A separate
48 dp jump control returns to the latest activity. Pending receipt recovery
appears before the full submitted question, and the resized keyboard viewport
keeps the composer available. These are source behaviors; simulator layout and
installed phone qualification have separate evidence.

The synthetic journey verifies the eight-turn bound, literal text rendering,
uncertain/malformed responses, structured context, reload and delayed scope
changes. It also checks delayed replies while reading, identical turns,
surviving-anchor and tall-row cap eviction, localized jump, language refresh,
natural End and reset. It checks actual 390 px/150% Chinese and English layouts,
bounded scrolling and keyboard access. No microphone or production provider is used.
Served Web files and family conversation quality remain separate delivery gates.
