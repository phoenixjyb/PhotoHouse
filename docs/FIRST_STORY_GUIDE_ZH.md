# 从一张照片上的回忆，开始第一个故事

照片下保存的家人回忆是**原始素材**；“我们的故事”里显示的是另外编排并保存的
故事；回忆集则把几个已保存故事连在一起。保存了照片留言，并不会自动生成故事。
这样可以保留原话，也让家人决定如何讲述和分享。

## 先在 Web 编排一个小故事

1. 登录，选择正确的相册库。在“照片与视频”找到同一次活动的几个画面。
2. 点击“编排一个故事”，先选择 2–6 个有关联的画面；也可以从一个主题进入。
   选择界面每次有数量上限，不必一开始编排整本家史。
3. 给草稿一个工作标题，点击“整理章节”。检查每章的画面和参考资料；AI 描述
   仍是待核实的观察，不能因为已出现就当成事实。
4. 把你知道的经过写进章节：当时在哪里、和谁在一起、为什么值得记住。
   不确定的日期和名字可以写“不确定”，不必补齐一个看似完整的故事。
5. 使用预览检查顺序和文字。预览和下载草稿都不等于保存到相册库。
6. 确认愿意让这个相册库的成员看到后，点击“保存到相册库”，等到明确成功。
   结果不确定时使用原来的重试入口；不要重新创建一份相同故事。
7. 返回“我们的故事”，重新打开并检查标题、章节和来源。原来的照片留言仍然
   是独立素材，不会因编排而被改写。

只有实际提供了相应功能时才会出现 AI 标题、自动分组或编辑建议入口。它们有
单独的服务和质量验收要求；没有入口时可以手动编排，并不是需要再次上传照片。

## 再编排一本回忆集

保存两个相关故事后，打开“编排一本回忆集”，选择并调整故事顺序，写下引言，
确认后保存。重新打开，使用目录逐章阅读。加入回忆集不会把素材分享给其他
相册库，也不会自动发布到 TV。

手机的故事／回忆集入口可继续阅读和补充；具体可用操作以安装版本和当前
相册权限为准。[状态页](PROJECT_STATUS.md)区分源码、候选包和已发布版本。

## 交给助手继续找与读

先发送“找已保存的回忆”，确认结果卡片指向刚才的故事，再打开或明确开始朗读。
照片留言、未保存草稿和已保存故事是不同的检索对象；没有已保存故事时，故事
搜索为空不代表照片或留言丢失。

[v59 候选试用](../clients/android/docs/PHONE_V59_TEST_GUIDE_ZH.md)说明首章／引言的
分段朗读和连续语音；[v60 阅读试用](../clients/android/docs/PHONE_V60_TEST_GUIDE_ZH.md)
补充字号和阅读导航。先确认实际版本，再测试对应功能。

口述转写到编辑框只是文字输入方式。是否保存原始录音，取决于有没有另外明确
提交原声附件；不能因为显示了转写文字就认为录音也已保存。长篇口述记录器仍是
[后续计划](FAMILY_MEMORY_HUB.md)，不能用连续助手语音代替耐久录音保存。
