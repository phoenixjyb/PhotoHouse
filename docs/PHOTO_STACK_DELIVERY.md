# Complete photo-grouping delivery

The next product milestone is a gallery in which similar photos take one place,
every original can still be opened, and each member can adjust their own view.
Deliver that experience before adding more grouping algorithms. Record search
latency as diagnostic information rather than making a particular response-time
target a prerequisite for this feature. Existing frozen qualification results
retain their original limits and outcomes; an advisory timing policy does not
turn a failed run into a pass or waive access, data, resource or cleanup checks.

This checklist records source capability and remaining delivery work. It does
not assert the current Windows schema, installed APK, active worker or family
acceptance. Recheck those identities when preparing the coordinated operation.

The grouping rules already allow capture times within five minutes with an
eight-bit perceptual-hash distance, or a stricter four-bit same-uploader/batch
fallback when reliable capture times are absent. Complete-link cohesion, date
conflict checks and access boundaries remain intact. Missing hashes or unusable
dates mean insufficient evidence, not a conclusion that photos are different.
An initial cover is a representative in gallery order, not an AI quality winner.

## Finish the existing path

1. **Freeze the combined source.** Keep the current reviewed search and AI changes,
   flags, routes, configuration and gateway entry. Grouping does not require a new
   semantic provider or model activation. Compare source members and manifests,
   rather than replacing the service with an older grouping-only package.
2. **Finish private-copy qualification.** Verify the retained backup inventory,
   then qualify the exact migration, launcher and scoped worker on approved
   private copies. A generated database pass does not establish compatibility
   with a retained household copy. A copied database is never a replacement for
   the current authoritative primary or deletion journal.
3. **Prepare one guarded activation.** Use the current installed API and writer
   roster, fresh stopped-writer backups and restore rehearsals. Qualify every
   entry that will restart against f2. Apply the additive migration without
   changing unrelated flags, then build selected-library indexes. Use the
   existing [operations contract](PHOTO_STACK_OPERATIONS.md); do not infer
   production authority from source checks or an earlier operation's approval.
4. **Keep grouping current.** Configure the reviewed CPU refresh entry and its
   stop/restart behavior. Runnable scoped pHash work postpones a sweep; failed
   records stay evidence. Unchanged sweeps must not rebuild. Verify that new
   approved photos eventually enter the index while originals remain readable.
5. **Deliver paired clients.** Verify the served Web assets and exact phone
   artifact against the API. Publish only through the existing release workflow.
   Keep ordinary gallery fallback available when v2 is absent; do not treat an
   access or server error as permission to hide the error and use stale data.
6. **Accept the family experience.** Complete the journeys below before marking
   library-wide grouping available. A working gallery, persisted private choice,
   worker progress and device interaction are separate acceptance results.

The worker schedule, live schema transition, API restart, APK signing/publication
and family-data inspection each retain their applicable operation authority.
Preparation remains local while another workstream owns the shared Windows lane.

## Family acceptance journeys

Use generated media for development and an authorized library for the family
trial. Keep asset numbers, account identities and diagnostic metadata in private
evidence. Do not upload household photos to public issue trackers.

| Journey | Expected result |
| --- | --- |
| Open a burst in All/Photos | One representative with a clear count; unrelated photos remain easy to scan |
| 展开 → open a member → return → 收起 | Every original opens; the viewer includes all members; the group remains understandable and focus returns to its control |
| Choose another cover and reload | v2 retains the current account's choice; a second account's cover is unchanged |
| 单独显示 one member | That photo remains visible by itself, while the remaining members stay accessible |
| 重置全部相似照片设置 | Only the current account/library's display choices reset; originals and other accounts are untouched |
| Cross a raw-page boundary | A complete v2 stack occupies one visible position and does not repeat on another page |
| Upload another similar photo | The approved photo is visible individually before refresh and is considered by a later successful sweep |
| Change library/account or revoke access | No late response, private choice or protected image leaks into the next scope |
| Interrupt a preference save | Read-reconcile the current result; do not automatically replay the write |
| Index absent, unsupported or malformed grouping | Safe ordinary-photo display; a 404 may negotiate v1, while other errors retain the normal recovery flow |
| Large Chinese text, keyboard or phone navigation | Counts and controls remain readable, tappable and reachable without trapping focus |

The page-local v1 fallback keeps choices only in the current view. Persistent
choices and cross-page consistency belong to v2; do not use a v1 trial as proof
that those features are active.

## Remaining product work

**Similarity calibration:** inspect the requested missed pairs under separately
authorized metadata access. Check usable hash coverage, reliable capture times,
same-batch eligibility, actual hash distances and page/index membership before
loosening thresholds again. Record the reason for a missed pair privately. A
broader legacy hash backfill needs a bounded plan; never reset unrelated failed
tasks just to increase coverage.

**TV:** design a compact cover/count view, remote expansion and reliable return
focus against its separate Home catalog. Decide the anonymous catalog's grouping
policy explicitly. Do not copy a signed-in member's private preferences into a
LAN-visible projection. Ordinary TV browsing can continue while this separate
client increment is prepared.

**Presentation:** the Web expanded region already has dedicated grouping and
focus behavior. Review the phone's expanded-member layout on a responsive
emulator before changing it, then verify the resulting APK. A source screenshot
does not establish installed or physical-device behavior.

**Stories:** similar-photo stacks remain presentation choices. They do not merge
albums, assign activities, share a memory, delete duplicates or let AI rewrite a
family story. Those editorial actions keep their own reviewed contracts.

## Record delivery without overstating it

Keep separate receipts for committed source, package identity, generated checks,
native private-copy checks, live activation, worker/index state, Web/APK delivery
and family/device acceptance. Record timings and slow paths as diagnostic data.
A partial process scan, failed readback or missing offline proof remains a gap;
any separately reviewed limited owned-attempt release does not complete this
feature or retroactively qualify its failed operation.
