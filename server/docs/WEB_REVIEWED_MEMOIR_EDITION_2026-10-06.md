# Web reviewed memoir edition increment

## Source scope

This increment follows the backend integration and changes the protected memory-community UI and its local qualification harness. A source import does not update an installed package or a served WebUI.

A ready whole-memoir suggestion now offers an explicit review action to an editor.
Opening it checks the separate default-off edition capability and fetches the
actor-private proposal. Job completion itself performs neither operation. The
original generated draft and source labels remain available in a collapsed panel;
the review form displays named chapters, title, chapter text and a count of the
proposal's citations. Chapters expand independently and retain their open state.

The editor can change title and narration, while chapter order, source pointers
and review questions remain bound to the proposal. Every edit clears the explicit
review checkbox. Saving freezes one body and mutation identity. An uncertain or
malformed receipt leaves that exact request available for explicit retry; there
is no automatic retry. Pending saves block conversation switching and a new model
request. Leaving edited text requires a discard decision; IME composition blocks
that transition. Account/library clearing always discards protected transient data
and fences late requests.

A content-free save receipt does not stand in for reading. The read button clears
previous manuscript text before fetching a freshly authorized edition. Changed or
invalidated sources, malformed responses and read failures leave no prior prose.
A temporary/default-off opening has an explicit capability recheck action.

## Qualification

The browser test uses the existing cached Chromium headless shell and a pipe to
a real synthetic ASGI application/SQLite fixture, without starting a listener.
It checks default-off and malformed capability handling, explicit review, edited
wording, IME/navigation preservation, lost-save receipt and identical retry,
malformed changed-source response, source scrubbing and a late proposal after
account clearing. Chinese and English use a 390px viewport with 150% text; both
have explicit no-horizontal-overflow checks. Screenshots of the review and saved
states were inspected. Browser page errors and external requests were both zero.

The harness reuses a seeded ready narrative job instead of invoking a provider.
Its scrub command invokes the edition eraser without deleting the fixture
contribution; actual contribution deletion and journal replay are covered by the
separate Python erasure suites. This browser run does not qualify generation,
physical source deletion, model output quality or a live deployment.

The existing community browser journey also passed all 22 reported checkpoints,
including voice, IME, thread history and the 24-chapter directory. The reader leave
browser check and the deterministic community UI contract harness passed. No
real recording, family media, live origin, model or device was used.

Example command from the repository root:

```sh
PH_BROWSER_PYTHON=/path/to/qualified/python \
PH_BROWSER_EXECUTABLE=/path/to/cached/headless_shell \
node server/tests/security/test_memory_book_edition_browser.cjs
```

shelf/reader independent of the private ready job, approved source-detail jumps,
phone adoption and native restore/worker qualification remain to be completed.

types are not all covered. Edition activation remains off. No Windows switch,
model run, signed APK, OTA update or TV publication belongs to this increment.
